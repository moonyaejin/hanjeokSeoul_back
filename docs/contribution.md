## 🙋‍♀️ 주요 기여 (백엔드)

본 프로젝트에서 저는 **백엔드 전반의 아키텍처 설계, 핵심 기능 구현, 배포 환경 구성**을 주도했습니다.  
단순히 API를 만드는 것에 그치지 않고, 서비스의 안정성과 확장성을 고려한 구조를 설계하는 데 집중했습니다.

---

## 1. 시스템 아키텍처 및 DB 설계
- `Place`, `Area`, `User`, `Review`, `Suggestion` 등 주요 엔티티 모델링 및 정규화.
- 정적 장소 데이터 + 실시간 인구 API 데이터 + 사용자 리뷰 데이터를 **통합 관리**할 수 있는 DB 스키마 설계.
- ERD 설계 및 팀원들과 공유 → 데이터 파이프라인과 API 구조 협업에 활용.

---

## 2. 위치 기반 추천 알고리즘 구현
- 사용자 좌표와 서울시 기준 지역(80~116개 지점) 간 **거리 계산 알고리즘** 구현.
- 카테고리(식당/카페/공원)별 필터링과 실시간 인구 데이터를 결합해 **혼잡도가 낮은 장소 추천 로직** 개발.
- 성능 최적화를 위해 **Haversine 공식** 대신 단순 거리 비교 방식으로 개선.

---

## 3. 커뮤니티 제보 및 이미지 업로드 처리
- **제보 등록 → 관리자 승인 → 리뷰 등록 → 이미지 업로드** 흐름을 엔드 투 엔드로 구현.
- 멀티파트 이미지 파일을 AWS S3에 저장, URL을 DB와 연동.
- 이미지 누락 대비 **fallback 기본 이미지 로직** 추가 → UX 안정성 확보.

---

## 4. CI/CD 및 HTTPS 대응
- GitHub Actions를 활용해 **Docker 빌드 → ECR 업로드 → EC2 배포** 자동화 파이프라인 구축.
- 이후 Render로 전환하여 HTTPS 및 SSL 인증서를 자동 적용 → 모바일 앱 심사 조건 충족.
- 덕분에 배포 과정이 30분 이상 단축되고, 운영 환경에서도 HTTPS 통신 안정성 확보.

---

## 5. API 문서화 및 프론트 협업
- Swagger 기반 전체 API 명세서 작성, 팀 내 공유.
- 응답 포맷과 예외 메시지를 통일해 프론트엔드 개발자가 빠르게 연동 가능하도록 지원.
- 신규 API 추가 시 자동 문서화 파이프라인을 구축해 협업 비용 감소.

---

## 6. 문제 해결 경험 – Expo 빌드 이슈
- 공모전 마감 직전, Android 빌드 실패 문제가 발생.
- SDK 버전 충돌, 환경변수 누락, fallback 처리 등 원인을 단계적으로 분석.
- 단독으로 문제를 해결하고 최종 빌드 완료 → **서비스를 앱스토어에 제출할 수 있는 수준으로 완성**.

---

## ✨ 정리
이번 프로젝트에서 단순히 기능 구현뿐 아니라,

- **문제 해결 능력** (빌드 이슈 해결),
